\subsection*{What the comparison actually establishes}
\begin{itemize}
\setlength{\itemsep}{3pt}
\item \textbf{Low-level tracking improves relative to matched PID.}
Retrained SAC has \SACPIDRMSEGainPct\% lower mean RMSE and wins
\SACPIDRMSEWins/5 paired cases. PID and SAC have identical actual market
contracts in every window. The smaller SD describes these evaluation cases;
it is not a claim about stability across independent training runs.
\item \textbf{It is not a win on every objective.}
SAC minus PID is \SACPIDRevenueDelta~USD in 24-hour regulation revenue,
+\SACPIDAgeIncreasePct\% in service aging, and \SACPIDCashDelta~USD in
26-hour grid cash. PID also has the higher mean native rewards.
The biased peak-date Table 2 comparison is a different panel; its
SAC/PID economic advantage does not automatically transfer to this nominal one.
\item \textbf{The learned macro is not an improved bidding result.}
It has \HighAcceptedBids/\HighBidWindows\ accepted bids:
mean ask \HighMeanBidPrice\ versus mean posted price
\HighMeanPostedPrice~USD/MWh. It retains the standing 5 MW commitment.
The observed low revenue and reserve failures are not hidden by selecting
another checkpoint after seeing this table.
\end{itemize}

These are descriptive results for fixed policies and five noise cases,
not significance tests or fresh calendar-date generalization.

\subsection*{Why the old and new columns cannot simply be subtracted}
\begin{itemize}
\setlength{\itemsep}{4pt}
\item \textbf{Reward definitions changed.}
The archived paper explicitly defines throughput reward as
$\alpha\theta$ and uses mean LMP times normalized facility power as its
electricity-cost proxy. The old code implements those expressions.
Served-dynamic-work reward and actual PCC electricity expenditure are
deliberate changes of reward meaning and scale, not repairs to SAC's
actor/critic update equations. Negative corrected rewards are not directly
comparable to the old near-one reward values.
\item \textbf{The simulated response and inputs changed.}
Corrected work/idle-power handling, consistent electrical and thermal
load, a complete modeled grid-import response boundary, a declared
nominal reference, timestamp-faithful replay and isolated random streams
change the trajectories seen by every controller.
The original nominal loader advanced a five-minute source row every
five seconds; matching a day label does not recreate matching inputs.
\item \textbf{Evaluation and policy provenance differ.}
Fast-tick RMSE is used here, aging includes the first transition,
random-action streams are seeded independently, and classical controllers
are fresh per case. The original Table 1 producing records are insufficient
to prove which earlier metric-export path supplied each number.
New SAC checkpoints were selected before this evaluation, not to maximize
this new table.
\end{itemize}

Thus, comparing 229 with 272.6 kW across these panels is neither an isolated
algorithm improvement nor an isolated regression. The valid current
SAC/PID comparison is \textbf{within Table 1A}, where both use the same
declared physical and evaluation protocol.

\subsection*{Exact primary definitions}
For each five-second service tick, let $G_t$ be actual signed grid-import
power and $F_t^{\rm ref}$ the continuing nominal reference in MW:
\[
 R_t=1000(F_t^{\rm ref}-G_t),\qquad
 {\rm RMSE}=\sqrt{\frac{1}{N}\sum_{t=1}^N(D_t-R_t)^2}.
\]
This is not RMS of macro-window mean errors. Regulation revenue is summed
using actual commitment, performance and executed duration.
Electricity expenditure is $\sum_t {\rm LMP}_t G_t\Delta t_{\rm hours}$.
Low reward is averaged over fast ticks; macro reward over returned macro
windows. Warning fraction counts post-step ticks with either zone
temperature at least $33^\circ$C. Aging is
$10^4(a_{\rm end,24h}-a_{\rm reset})$, including the first transition.

The additional gates require full service, service-end SOC $\geq0.20$,
backlog at most 1\% of arrived work, warning fraction at most 0.01,
work conservation and recovery closure. If any planned case were incomplete,
no full-horizon primary means would be reported for that row.
Qualification failures are never removed from otherwise-complete cohort means.

\textbf{Exposure and configuration.}
Day 0 was a training start date, so this is not a fresh calendar holdout.
That does not prove exact-cell or trajectory-level training exposure.
Recorded training/native YAML hashes match; the Table 2 recovery YAML changes
only three relative data paths to absolute paths. No static market, plant
or reward-scalar mismatch was found. This is not a causal explanation of
the high-level policy's rejected bids.

\subsection*{Verified original-code issues, versus deliberate changes}
The companion \texttt{ORIGINAL\_SAC\_AUDIT.md} provides exact original-revision
and corrected source links, numerical counterexamples and scope limits:
\begin{itemize}
\setlength{\itemsep}{3pt}
\item \textbf{Physical inconsistencies:} command-based flex credit despite
unchanged served work; idle power treated as deferrable work; heat/electrical
load disagreement; incomplete response-meter boundaries.
\item \textbf{Causal interfaces and clocks:} stale market offers and low-level
commitments; malformed reset context; ignored custom config; accelerated
source replay; shared random-stream coupling; nominal-duration settlement
for an early-ended macro window. The returned RegD telemetry, not the
original fast reward's observed-signal timing, was mismatched.
\item \textbf{Trainer/configuration defects:} the checked-in macro SAC trainer
used a rule executor rather than the claimed frozen low SAC; ignored
profile/device settings; misleading checkpoint seed labels; wrong callback
interfaces and a 287-tick ``survival'' threshold for a 17,280-tick task.
This proves checked-in behavior, not an unknown historical model's producer.
\item \textbf{Reporting defects:} window-mean instead of fast-tick macro RMSE,
omitted first aging increment, missing no-agent fast metrics, RNG/controller
state leakage, survival based on macro call count, and inconsistent export
or filtering paths. Missing historical producing records limit attribution.
\end{itemize}

The throughput/cost-proxy redesign, standardized reference, wider training
coverage, independent fits, early checkpoint selection and added recovery are
not all ``bug fixes.'' No one-factor ablation assigns the gains to each change.
No faulty SB3 SAC update equation was established.
The original simple BESS already used actual SOC-limited output.

\textbf{Remaining or newly introduced limitations are not concealed.}
These include imperfect RegD window centering, a fixed-five-second calibration,
the voltage/PCC interface and energy-equivalent workload approximation.
A newer corrected macro-Box sampling-metadata defect is separately labelled:
finite real-observation inference works, but generic observation-space
sampling can fail. The frozen simulator and checkpoint bytes were not
silently changed to improve this table.
